# Honest web performance audit
Quick/static mode: inspect actual framework/rendering model for structural anti-patterns; every finding is potential impact; scorecard value NOT MEASURED. Source cannot produce LCP/INP/CLS.
Deep mode: parse provided Lighthouse JSON, PSI lab plus loadingExperience field data, CrUX p75 rolling 28-day, DevTools trace or an actually available live capture. Label every number with source/artifact/environment. Lab single-run is not field experience; rolling field is not instant canary response. Unparsed trace parts remain unparsed. No API key disclosure or invented data.
Scorecard columns metric/value/unit/source/target/status. Illustrative good CWV: LCP<=2500ms,INP<=200ms,CLS<=0.1; project policy/current official authority governs adopted thresholds. Report empty unavailable cells rather than estimating. Lighthouse >=90 and initial JS<200KB are contextual examples, not universal standards.
Review areas: CWV attribution/LCP image/layout shifts/long tasks, loading waterfall/TTFB/fonts/third-party facade, rendering/state duplication/re-render/effect loops/listeners/layout thrash/virtualization, network compression/cache/pagination/deduplication/waterfalls. Preserve bfcache where compatible; browser APIs such as speculation/view-transition/LoAF/yield need version/current support checks, not unconditional use.
Finding: location, symptom/source, observed vs potential impact, likely cause and actionable next measurement/fix. A remote metric, live browser capture or platform API is optional and must be honestly unavailable rather than fabricated.
