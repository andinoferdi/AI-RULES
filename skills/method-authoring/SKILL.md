## Procedure

1. Construct realistic baseline before advice: wrong action/output and observable signal. No-guidance control must exhibit failure; otherwise stop adding speculative rules.
2. Match form to failure: discipline gets precise boundary/counter; wrong shape gets positive recipe; omitted element gets artifact slot; conditional gets observable predicate.
3. Write minimal contract: purpose, trigger/non-trigger, prerequisites, procedure, ownership, permission, output, verification, example/anti-pattern, fallback/provenance. Bundle heavy reference locally and lazy-load.
4. Test by consumer use: application/variation/gaps for technique, recognition/counterexample for pattern, retrieval/application for reference, combined realistic pressure for discipline. Schema/code examples prove limited properties, not model compliance.
5. When authorized evaluator exists, compare no-guidance and candidate across several fresh contexts. Read flagged outputs; quoted counterexamples fool token scoring. Record variance/limits.
6. Revise only observed failures, rerun affected scenarios and preserve legal/self-containment. No user-work deletion, forced evaluators, push or runtime prompt fetching.
