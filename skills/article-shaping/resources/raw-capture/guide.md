# Collect raw writing fragments

Internal method ID: `writing-fragments`. Conditional adaptation: use only for the concrete requested context; upstream beta/frozen status does not imply general readiness.

## Purpose and selection

Preserve useful raw observations before imposing an article structure.

Activate for: An explicit exploratory writing session seeking material rather than a finished argument.

Do not activate for: A fixed-pile article-shaping task or permission to invent personal anecdotes.

## Inputs and dependencies

User topic and actual observations, selected fragment file, current on-disk user edits and requested revision scope.

Use resources progressively: [worked procedure and example](resources/worked-example.md). It is local and self-contained. Optional project tools are discovered when needed, never installed merely to load this method.

## Procedure

1. Capture useful material from the first prompt onward. Choose/reuse the destination once and reread it before each write.

2. Explore heterogeneous material: precise sentence, claim/reason, vignette, code/example, half-thought, quote, cluster, complaint or compact leading metaphor.

3. Keep a working H1 and fragment bodies separated by horizontal rules. Do not add outlines, tags, unnecessary metadata or section headings while exploration is open.

4. Append meaningful fragments without repeated save dialogs. Preserve the user's wording when its voice is the point and never invent experience as theirs.

5. Push for a compact useful term when a recurring observation needs a name, but keep alternatives open rather than locking an argument prematurely.

6. Respect targeted cut/rewrite/merge requests in place while leaving unrelated fragments and user edits intact. Shaping/publishing remain separate requested work.

## Outputs and verification

On-disk edits survive, raw fragments remain readable to the author, no imposed outline or invented facts enter, and revisions stay within requested scope.

Apply the worked example to observe an artifact and independent expected outcomes. Its deterministic result proves only that bounded procedure; it does not prove model routing, live host parity or optional external tool execution. Record actual command/tool, current content identity, result and unresolved limits before claiming success.

## Example and anti-patterns

Positive request: “Interview me for raw writing fragments without deciding an outline yet.”

Negative request: “Turn this fixed pile directly into a final article.”

Turning every observation into an essay paragraph, overwriting the pile, organizing before discovery or assigning made-up personal history.

## Fallback

Offer candidate fragments explicitly labeled as drafts when the author has not supplied lived evidence. Beta use is conditional on a writing request.
