# Tracker notes

Formats for the attention list, needs-info notes, closing comments and resumed triage. Every
text meant for the tracker starts with the project's disclaimer line (shown here as the
default). Labels in examples are role names; write the tracker's own strings.

## Attention list

Three buckets, each oldest first, with a count per bucket and one line per item. Tag every line
`[issue]` or `[PR]`. Then list what you left out and why, so the maintainer can see nothing was
dropped.

```markdown
## Needs your attention (6)

### Never triaged (3)
- #41 [issue] 2026-09-02 · Reminders skip the day after a clock change (bug report)
- #44 [PR] 2026-09-05 · @ana adds `--limit` to `notes list`
- #47 [issue] 2026-09-09 · "Let me run my own scripts on save"

### Needs triage (2)
- #38 [issue] 2026-08-30 · Search ignores accents
- #46 [issue] 2026-09-07 · Export notes as Markdown

### Waiting on the reporter, and the reporter replied (1)
- #35 [issue] 2026-08-21 · Sync stops after sleep — reporter answered 1 of 2 questions on 09-10

Left out: #36 and #40 (ready-for-agent), #39 (needs-info, no reply since the notes),
#45 [PR] (maintainer @lee, in progress). Needs a decision: #42 carries both needs-info and
ready-for-agent.

Which one first?
```

## Needs-info notes

Capture everything settled so far under "established", so nothing is lost, then ask only what
is still open. Each question names exactly what you need: a command, its output, a version, a
file's state, an observation.

```markdown
> *This was generated by AI during triage.*

## Triage Notes

**What we've established so far:**

- Sync runs normally until the laptop sleeps; the reporter is on version 2.3.1.
- Verified: a manual `notes sync` after waking works here, so the sync itself is not broken.

**What we still need from you (@reporter):**

1. After waking, what does `notes sync --status` print?
2. Is the "Sync in background" setting on or off?
```

Never "please provide more information".

## Resuming from earlier notes

When the item already has triage notes, read them and the replies after them, then present
the updated picture before anything else:

```markdown
Earlier notes asked 2 questions. Answered: version (2.3.1, macOS 15). Still open: the
`notes sync --status` output. The reply returns this item from needs-info to needs-triage.
```

New notes copy the answered facts into "established" and repeat only the open questions.

## Ready-for-human note

Use the agent brief template and add one line after the summary:

```markdown
**Why a person:** the fix needs a decision on which sync conflicts win, which only the
maintainer can make.
```

## Closing comments (wontfix)

Already built:

```markdown
> *This was generated by AI during triage.*

This already exists: `notes search --title-only WORDS` searches note titles and skips the
bodies ("headline search" in your request is what the project calls a title search). See the
README section "Search". Closing because the feature is already available.
```

Rejected bug:

```markdown
> *This was generated by AI during triage.*

Thanks for the detailed report. Notes are sorted by last edit on purpose, so a note moves to
the top when you change it. That is the intended behavior and will stay, so we're closing this.
```

Rejected enhancement (after the maintainer confirmed):

```markdown
> *This was generated by AI during triage.*

The project does not load plugins or user scripts; the reasoning is in
`.out-of-scope/plugin-system.md`, which now lists this request too. Closing as wontfix.
```

## Progress note (needs-triage)

Only when there is progress worth recording:

```markdown
> *This was generated by AI during triage.*

Reproduced on main with `notes search café` (no results, expected one). Waiting for a maintainer
decision on whether accent-insensitive search should be the default.
```
