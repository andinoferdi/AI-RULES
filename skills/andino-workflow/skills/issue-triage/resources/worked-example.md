# Worked example: one triage session end to end

A synthetic project, `notes`, a command-line notebook. Its tracker configuration maps the
roles to labels (`kind/bug`, `kind/feature`, `status/triage`, `status/info`,
`status/agent`, `status/human`, `status/wontfix`), names maintainers @lee and @kim, and
requires `> *This was generated by AI during triage.*` as the first line of AI text.

The maintainer writes: "What needs my attention? And look at #41 — if it reproduces, make it
ready for an agent. Tell me what you think of #46."

## Step 1: authority lines

```text
attention list   read only
#41              may write: status/agent + brief, only after the bug reproduces
#46              draft only
```

## Step 2: the attention list

The list is the format in [tracker notes](tracker-notes.md#attention-list). #45 is @lee's
pull request, so it is left out with that reason; #42 carries `status/info` and
`status/agent` together and is named as needing a decision.

## Steps 3 to 5 for #41

#41 [issue] "Reminders skip the day after a clock change": a daily reminder did not fire on
2026-03-29. No earlier notes. Labels: none, so no conflict. Already built: no; searched
`next_occurrences`, the scheduler tests, `notes remind --help` and the changelog for
daylight-saving handling. Prior rejection: none among 3 files in `.out-of-scope/`.

Verification in a scratch folder:

```text
$ python -c "from notes.reminders import *; r = daily('08:00', 'Europe/Berlin', start='2026-03-27'); print(next_occurrences(r, 3))"
['2026-03-28T08:00+01:00', '2026-03-30T08:00+02:00', '2026-03-31T08:00+02:00']
```

Verdict: CONFIRMED. `next_occurrences` adds 24 hours in UTC, so the local day that is 23
hours long is skipped.

## Steps 7 and 8 for #41

The authority line covers this outcome and its condition was observed, so the brief from
[the bug example](agent-brief.md#example-bug) is posted with the disclaimer first, the labels
become `kind/bug, status/agent`, and the item is re-read from the tracker to confirm both.

## #46: a request that already exists

#46 [issue] "Export notes as Markdown". The glossary's term is Export; searching
`notes export --help` shows `--format md` already writes Markdown, and a test covers it.
Recommendation, as a draft:

```text
#46 [issue] Export notes as Markdown
Category: enhancement   State: wontfix (status/wontfix)   Was: status/triage
Verified: CONFIRMED - notes export --format md -> one .md file per note
Already built: notes export --format md (searched: export --help, export tests, README)
Prior rejection: none (3 files read)
Earlier notes: none
Recommendation: wontfix, because the feature already exists; no .out-of-scope record
Questions for the maintainer: none
Tracker change: draft, not posted
```

The draft comment is the "already built" text in
[tracker notes](tracker-notes.md#closing-comments-wontfix). It is not posted: the maintainer
asked for an opinion on #46, not an outcome. Recording #46 in `.out-of-scope/` would be wrong:
the project does this, so a later request for Markdown export must not look rejected.

## Run the example

This example uses only Python's standard library and writes inside the current working
directory. Read the code, then run it only in a fresh disposable directory. The main
repository's `scripts/check_andino_matt_methods.py --runtime-root <package>` executes this exact
block in a TemporaryDirectory and independently checks the semantic results. No project files,
index, external services or credentials are needed.

```python
from pathlib import Path
import json
issue={"category":"enhancement","state":"needs-triage","already_implemented":True,"evidence":"feature exists in fixture API"}
decision={"category":issue["category"],"recommended_state":"wontfix","reason":"already implemented","record_rejection":False,"external_write":False}
Path("triage.md").write_text("> This was generated by AI during triage.\nRecommendation: close as already implemented.\nEvidence: "+issue["evidence"],encoding="utf-8")
result=decision
Path("result.json").write_text(json.dumps(result,sort_keys=True),encoding="utf-8")
```

## What the observation establishes

Inspect `triage.md` and `result.json`: an already-built enhancement is recommended as wontfix
with no rejection record and no tracker write. The block demonstrates the decision rule only;
it does not show model behavior, live tracker writes or host routing.
