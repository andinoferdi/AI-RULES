For a shader change choose `threejs-shaders`; lighting `threejs-lighting`;
keyframe/skeletal animation `threejs-animation`; material work `threejs-materials`;
mesh construction `threejs-geometry`; picking/input `threejs-interaction`.
A combined shader-and-light task can select those two without unrelated members.
For complex procedural effects the technical advisor `threejs-skill-router` may
recommend a minimum set. Use `threejs-game-director` only for game-wide production,
not as a general dispatcher. Their recommendations yield to the current task,
project constraints, host invocation controls and Andino's single lifecycle.

Unknown-cause failures start with `systematic-debugging`. Add a domain specialist
only after evidence identifies the needed domain. Ordinary frontend requests do
not select these skills. The minimum set can change when requirements change;
release irrelevant methods and load newly selected permitted guides within the
already invoked family. Do not load all members for a broad request or install.

Resolve the family DISCOVERED -> AVAILABLE -> INVOKABLE -> ACTIVE -> USED with evidence per
[host contract](invocation-adapter.md). Missing, denied or explicit-only methods
are not bypassed through source-file reads; report UNAVAILABLE and a sufficient
native fallback. Also check any method/resource restriction; family invocation
never overrides one. Record guide loading separately from native family invocation.
An available irrelevant method is NOT_NEEDED. Search First owns
relevant library/version/alternative research; Focus owns communication.

Specialists return domain methods/results, evidence, limits and recommendations
into the existing plan. They own no task checkpoint, handoff or DONE decision.
On resume follow [handoff](handoff.md), check repo/environment drift and refresh
selected availability without replaying already supported work. Keep provider job
IDs/journals in the existing plan as technical state. For rendering or performance
claims observe the real renderer/browser and required target states; unavailable
checks remain NOT_VERIFIED. UI acceptance uses 360, 768 and 1440 px screenshots
under the existing UI coexistence policy. No separate browser or plan pipeline.
