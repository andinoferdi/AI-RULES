# Workspace and Isolation Guards

Internal Andino resource for `andino-delegation`. Operates under Andino Workflow governance.

## 1. Dual-Mode Workspace Architecture

The workspace protocol supports two isolation strategies across Linux, macOS, and Windows. The helper resolves scratch storage; it does not create a Git worktree or grant authority to do so:

```
Workspace Resolution:
├── Mode 1: Isolated Git Worktree (Opt-in / POSIX Native)
│   ├── Creates independent linked checkout via `git worktree add`.
│   └── Recommended when tasks perform extensive structural renames or branch isolation.
└── Mode 2: In-Tree Scratch Workspace (Default & Cross-Platform Resilient)
    ├── Target directory: `<repo-root>/.andino/delegation/<plan-slug>/`
    ├── Houses task briefs, implementer reports, diff packages, and progress ledger.
    └── Enforces zero git pollution via self-ignoring root marker `.andino/.gitignore`.
```

### Self-Protecting `.gitignore`

Upon initialization, the workspace creator ensures that `.andino/.gitignore` contains:
```gitignore
# Auto-generated by Andino Delegation
*
!.gitignore
```
The ignore rule hides generated contents from normal untracked-file discovery; it does not prevent an explicit forced add. Inspect the staged diff before committing.

### Isolated helper verification

For disposable tests, set `ANDINO_WORKSPACE_OVERRIDE` to a newly created temporary directory. `delegation_workspace.py`, `task_brief.py`, and `review_package.py` resolve plan workspaces beneath that override and do not create the repository `.andino/.gitignore`. Preserve the `plan-path` ownership marker and sibling workspaces. Pass `-B` or `PYTHONDONTWRITEBYTECODE=1` to every Python descendant so imports cannot leave caches in the checkout. Tests own only their temporary root; teardown never deletes the repository `.andino` directory.

## 2. Windows File-Locking & NTFS Defense

On Windows systems, background processes (Windows Defender, IDE indexers, shell extensions) frequently hold open file handles, causing:
- `PermissionError: [WinError 32] The process cannot access the file`
- `fatal: Unable to create '.git/index.lock': File exists`
- `EBUSY: resource busy or locked`

### Mechanical Invariants for Windows Survival

1. **Bounded Retry**: Retry only an observed transient error, at most twice with backoff. Do not retry denied actions or conceal persistent failures.
2. **Explicit File Closure**: Close owned handles with context managers or `Path` convenience methods. Another process can still retain a handle; do not promise cleanup of actively locked files.
3. **Lock Preservation**: Lock age alone is not evidence that a Git lock is stale. Do not prune `index.lock` automatically. Diagnose ownership and retain the blocked state unless removal is separately authorized and safe.
4. **Path Containment**: Resolve paths with `pathlib.Path`, verify actual ancestry rather than substring containment, and use forward slashes in emitted JSON/Markdown.
5. **Temporary Cleanup**: Use `TemporaryDirectory` for owned test roots and exercise read-only-file cleanup on Windows. Its permission reset does not release an active external handle; report that failure instead of deleting a parent or sibling workspace.

## 3. Compaction-Resistant Durable Progress Ledger

**Core Law**: The execution plan owns task status, decisions, acceptance evidence
and NEXT ACTION. A plan-specific journal supports detailed worker history; it does
not override the plan or create a second lifecycle. Both outrank conversational recall.
- In long-running sessions, Claude Code triggers automatic context compaction.
- Controllers that rely on memory routinely re-dispatch completed tasks, wasting hundreds of thousands of tokens and overwriting git commits.

### Ledger Format (`.andino/delegation/<plan-slug>/progress.md`)

```markdown
# Delegation Progress Ledger — Plan: docs/plans/auth-refactor.md
Plan ID: auth-refactor
Base Commit: f3a8c12
Current State: ACTIVE

## Task Execution History
- Task 1: complete (commits a1b2c3d..d4e5f6a, review clean)
- Task 2: fix round 1/5 (2 addressed, 0 open; commits d4e5f6a..b7c8d9e)
- Task 2: complete (commits d4e5f6a..b7c8d9e, review clean)
- Task 3: complete (commits b7c8d9e..f9a0b1c, 1 parked)
  - Ruling: parked — minor mock warning — Ruling: code stands — zero risk

## Deferred Minor Findings
- Task 1: minor (deferred): extract JWT_EXPIRY_SECONDS to constant
- Task 3: minor (deferred): simplify header parsing regex

## Active Frontier
- Task 4 (deps: [Task 2, Task 3]) -> READY FOR DISPATCH
```

### Post-Compaction Recovery Protocol
1. Read the authoritative plan and this plan's supporting journal; reconcile any
   disagreement against current source and actual acceptance evidence.
2. Inspect live workers, partial reports and owned committed/staged/unstaged/new
   bytes. A fix-round record does not prove that its worker is still running.
3. Verify recorded commits and source/check/environment identities. Reuse valid
   completion evidence; invalidate changed producers and affected dependents.
4. Reuse only the exact still-valid approved wave. Failed, stopped or quota-limited
   workers need go-ahead before resume/replacement. Never redispatch completed valid
   tasks. Parent may continue inline after the worker relinquishes ownership.
5. Update current state and NEXT ACTION in the plan. Checkpointing does not require
   a context-reset command; use compaction only when actually exposed and useful.

## 4. Workspace Teardown and Cleanup

1. **Selective Deletion**: After final review, retain the ledger unless teardown is authorized. Before deleting an owned plan-specific directory, inspect its resolved path and `plan-path` marker, verify that it belongs to this plan, and preserve acceptance evidence in the authoritative plan. Never execute a deletion from an unchecked slug or a path copied from untrusted output.
2. **Sibling Isolation**: Never delete parent `.andino/delegation/` or sibling plan directories (`.andino/delegation/<other-plan>/`), which may belong to concurrent or paused tasks.
3. **Emergency Eject**: If a plan is aborted or circuit breaker trips, leave the workspace and ledger intact to allow human post-mortem and manual resumption.
