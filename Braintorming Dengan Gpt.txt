### Ada satu perubahan yang saya sarankan di `routing.md`

Sekarang konsep Anda kurang lebih:

```text
if installed:
    use specialist
else:
    use available method
```

Saya akan ubah menjadi:

```text
if installed:
    use specialist when relevant

elif dependency is REQUIRED for requested outcome:
    report missing dependency
    recommend official installation
    stop only the affected capability

elif dependency is RECOMMENDED:
    use fallback
    mention installation only when materially useful

else:
    continue without it
```

Jadi **missing skill tidak otomatis menjadi blocker**, tetapi agent juga tidak diam saja ketika ada capability yang jelas akan membuat task jauh lebih baik.

### Soal memasukkan third-party source ke repo

Saya hanya akan vendor dependency jika Anda memang sengaja membuat fork, perlu patch sendiri, membutuhkan offline/reproducible bundle, atau upstream tidak lagi dapat diandalkan. Kalau itu terjadi, taruh terpisah seperti:

```text
vendor/
└── some-skill/
    ├── UPSTREAM.md
    ├── LICENSE
    └── ...
```

dan simpan `upstream repo`, `commit SHA`, `license`, `vendored date`, serta local modifications.

Saya **tidak menyarankan Git submodule sebagai default runtime distribution** untuk project Anda. Installer user menjadi lebih rumit, clone biasa bisa tidak membawa dependency, dan branch-based packaging Anda sekarang malah menjadi lebih sulit dirawat.

Lisensi juga harus diperiksa sebelum vendoring. Beberapa project yang Anda gunakan memang memakai lisensi permisif, misalnya Taste menyatakan MIT dan metadata UI/UX Pro Max saat ini juga MIT, tetapi itu tidak berarti semua dependency otomatis boleh Anda salin tanpa memperhatikan attribution dan perubahan lisensi berikutnya. ([GitHub][10])

# Dua dimensi: Package × Host

Jangan tulis logika seperti:

```python
if package == "context7" and host == "codex":
    ...
elif package == "context7" and host == "claude":
    ...
elif package == ...
```

Kalau 20 package × 4 agent, kode Anda akan cepat menjadi monster.

Pisahkan dua tanggung jawab.

**Package adapter** mengetahui:

```text
Context7:
type = MCP
runtime = Node
command = npx -y @upstash/context7-mcp
supports_remote = yes
verify = connection/check
```

Sedangkan **host adapter** mengetahui:

```text
Codex:
how_to_install_skill()
how_to_add_mcp()
where_global_skills_live()
how_to_verify_skill()
how_to_list_mcp()
```

Lalu orchestrator menggabungkannya.

Misalnya Context7 + Codex akhirnya menjadi kira-kira:

```bash
codex mcp add context7 -- npx -y @upstash/context7-mcp
```

yang memang sesuai dokumentasi Codex MCP saat ini. ([OpenAI Developers][6])

Context7 + OpenCode bisa menggunakan mekanisme:

```bash
opencode mcp add ...
```

OpenCode bahkan punya dukungan global dan project-level MCP. ([OpenCode][7])

Antigravity punya global MCP config di `~/.gemini/config/mcp_config.json` serta workspace config di `.agents/mcp_config.json`. ([Antigravity][8])

Jadi capability yang sama dapat diterjemahkan ke host berbeda.
