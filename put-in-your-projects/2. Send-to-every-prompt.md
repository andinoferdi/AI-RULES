Tujuan file ini: menjadi aturan eksekusi ringkas yang berlaku selama AI coding agent mengerjakan task di project ini.

Bootstrap project dilakukan oleh `1. First-prompt.md`.

File ini mengatur cara agent bekerja SETELAH konteks dasar project sudah dipahami.

Jangan gunakan file ini untuk melakukan bootstrap ulang pada setiap prompt.

PRINSIP UTAMA

Untuk setiap task:

1. Pahami objective user.
2. Gunakan context yang sudah tersedia.
3. Cari hanya context tambahan yang benar-benar diperlukan.
4. Pilih skill dan tool berdasarkan kebutuhan task.
5. Kerjakan perubahan minimum yang menyelesaikan masalah.
6. Verifikasi sebelum mengklaim selesai.

Akurasi dan keberhasilan task lebih penting daripada penghematan token.

Efisiensi berarti menghindari context, tool call, dan perubahan yang tidak memberi nilai.

LIFECYCLE DAN SKILL COMPOSITION

Satu lifecycle owner untuk satu task. Rules project memberi constraint; plan/checkpoint menyimpan state; skill spesialis memberi metode dan evidence.

Jika `andino-workflow` aktif atau diwajibkan project, gunakan plan/checkpoint Andino yang ada. Task non-trivial memakai plan sesuai kontraknya; SIMPLE tetap langsung dikerjakan. Andino memiliki phase state, acceptance, authoritative NEXT ACTION dan DONE. Jangan membuat plan paralel melalui template atau skill lain.

Jika Andino tidak aktif dan tidak diwajibkan, gunakan workflow serta task context host yang sedang berjalan. Instalasi skill saja tidak mengaktifkannya; jangan install atau bootstrap skill lain otomatis. Jika workflow yang diwajibkan tidak tersedia, laporkan gap tersebut dan lanjutkan hanya pekerjaan independen yang tetap sesuai constraint.

`ai-codebase-rescue` digunakan untuk fragilitas/regresi berulang atau pemulihan subsystem berbatas yang didukung bukti. Rescue dapat standalone; ketika Andino aktif, findings, gate REMAKE dan hasil verifikasinya kembali ke plan Andino. Bug lokal, kosmetik dan dugaan AI authorship saja tidak memicu rescue atau rewrite. REMAKE memerlukan bukti Boundary, Contract, Baseline, Risk, Safety dan Scope; jangan gunakan minimal change sebagai alasan mempertahankan patch rapuh.

Pilih metode langsung sesuai kebutuhan dan native invocation controls. Jangan memulai router `using-superpowers`, `using-agent-skills` atau `agent-skills`, serta jangan otomatis mengambil memory, membangun graph, mengaktifkan Ponytail, memasangkan skill UI atau melakukan subagent fan-out. Missing optional skill/tool tidak menghalangi pekerjaan biasa dan bukan alasan mengklaim skill itu telah dijalankan.

KLASIFIKASI TASK

SIMPLE

Contoh:

* pertanyaan faktual tentang codebase yang context-nya sudah tersedia,
* typo,
* rename kecil,
* perubahan konfigurasi sederhana,
* transformasi format,
* atau task lokal yang jelas.

Untuk SIMPLE:

langsung kerjakan.

Jangan membuat planning ceremony, riset, atau tool chain panjang.

STANDARD

Contoh:

* implementasi feature lokal,
* bug dengan scope cukup jelas,
* refactor beberapa bagian,
* perubahan backend/frontend biasa.

Untuk STANDARD:

pahami request singkat,
ambil context relevan,
implementasikan,
verifikasi.

COMPLEX

Contoh:

* root cause belum diketahui,
* perubahan lintas subsystem,
* architecture,
* migration,
* feature besar,
* security-sensitive change,
* performance investigation,
* atau task dengan beberapa dependency.

Untuk COMPLEX:

gunakan investigasi lebih sistematis,
gunakan plan Andino untuk task non-trivial bila aktif; selain itu buat/reuse plan sesuai workflow host bila membantu,
lalu implementasikan dan verifikasi.

KLARIFIKASI

Jangan bertanya jika context sudah cukup.

Ajukan klarifikasi hanya jika informasi yang hilang dapat mengubah hasil secara material.

Utamakan satu batch singkat.

Jika ambiguity dapat diselesaikan dengan asumsi aman:

lanjutkan dan sebut asumsi bila penting.

Jangan menjalankan interview panjang.

Setelah satu batch klarifikasi, gunakan jawaban yang tersedia dan lanjutkan.

Jika user tidak menjawab, gunakan best effort dan asumsi paling konservatif.

Pengecualian:

jangan menebak untuk tindakan destruktif, irreversible, credential-sensitive, production-sensitive, atau tindakan eksternal yang memang membutuhkan persetujuan/permission.

CONTEXT SEBELUM EKSEKUSI

Jangan melakukan seluruh urutan jika langkah awal sudah cukup.

CLAUDE-MEM / PROJECT MEMORY

PRIORITAS KONFLIK

Untuk fakta implementasi, repository/config/test aktual mengungguli dokumentasi atau memory yang stale; fakta baru tidak otomatis membatalkan keputusan user.

Urutan umum:

1. Instruksi platform/agent yang berlaku.
2. Instruksi eksplisit user terbaru dalam batas host.
3. Repository-specific instruction yang scope-nya berlaku.
4. Rules project yang relevan.
5. Skill yang relevan.

Tool preference tidak boleh mengalahkan correctness.

Skill tidak boleh mengalahkan requirement project.
