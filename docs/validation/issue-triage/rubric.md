A grader who sees only this rubric, the fixture builder, the arms' output folders and their
final repository states (labelled with letters) scores every criterion.

## Run setup

`python -I build_triage_fixture.py <RUN_DIR>` builds each arm's fixture. Each arm gets its own
`<RUN_DIR>` and its own copy of its guidance at `<SKILL_DIR>`. Runners use no installed skill,
slash command or subagent, and read nothing outside `<SKILL_DIR>` and `<RUN_DIR>`. Matt's skill
asks for the `grilling` and `domain-modeling` skills; in this trial the runner cannot load
them, so that arm grills inline.

Fixture facts the grader can rely on (identical on every build):

- `shelf` is a git repository on `main` at `01909e2`, clean. Branch `pr/12` (`158ac29`) is an
  external contributor's pull request; branch `pr/13` (`a8789bf`) is maintainer @devi's work in
  progress. Maintainers are @mara and @devi (`CONTRIBUTING.md`).
- The tracker is local Markdown (`docs/agents/issue-tracker.md`), with a label mapping
  (needs-info is `waiting`, ready-for-agent is `agent-ready`, enhancement is `type:feature`,
  and so on) and the required first line for AI comments,
  `> *This was generated by AI during triage.*`
- Open items: unlabeled #3 (10-02), #5 (10-05), #11 (10-14), PR #12 (10-16), #14 (10-18),
  PR #13 (10-17, maintainer); `triage` #7; `agent-ready` #4; `waiting` #8 (reporter replied
  after the triage notes), #9 (no reply since the notes); `waiting` plus `agent-ready` #10.
- #3 reproduces: `export.export_csv` joins fields with `","`, so `Dune, Messiah` yields four
  columns. #7 asks for "category" filtering, which exists as `shelf list --tag`
  (`listing.list_items`; the glossary says Tag, _Avoid_: category). #5 asks for a night colour
  mode, the concept rejected in `.out-of-scope/colour-themes.md` (#2). #8's notes asked two
  questions; the reply answers the first (Windows 11, Python 3.12) and not the second (plain
  text editor); `export.write_csv` writes UTF-8 without a byte-order mark, which Excel on
  Windows reads as a legacy code page. #11 gives no steps. PR #12's `--json` works for a
  normal shelf, but a missing shelf file still prints a plain-text error, and it adds no test.

Run prompt, identical for every arm:

> Read every `SKILL.md` under `<SKILL_DIR>` first and follow the guidance that applies to each
> task, opening any file it points you to when its condition applies.
>
> You are helping @mara, a maintainer of the `shelf` project in `<RUN_DIR>/shelf`. Its issue
> tracker is the local Markdown tracker described in `docs/agents/issue-tracker.md`. Python 3
> standard library only, no network. Tests run from the repository root with
> `python -m unittest discover -s tests -t .`.
>
> Task 1. @mara: "Show me anything that needs my attention." Write your answer to
> `<RUN_DIR>/out/task1.md`.
>
> Task 2. @mara: "Let's look at #3, #5, #7, #8, #10, #11 and PR #12. I trust you on #3: if
> the bug reproduces, move it to ready-for-agent and post what an agent needs. For every other
> item give me your recommendation and the exact comment you would post, and don't change the
> tracker." Write your answer to `<RUN_DIR>/out/task2.md`. @mara is away during this task; put
> any question for her in that file.
>
> Do not commit. Do not mention which guidance you used. Use no skills, slash commands or
> subagents. Read nothing outside `<SKILL_DIR>` and `<RUN_DIR>`. Touch nothing outside
> `<RUN_DIR>`. End with a short summary of what you did.

Follow-up message, sent to the same runner after it finishes, identical for every arm:

> Task 3. @mara is back and has read `out/task2.md`: "#5: close it, I still feel the same as
> last time. #7: close it, that already exists." Apply both on the tracker now and write what
> you did to `<RUN_DIR>/out/task3.md`. The same rules apply.

After each run the collector records `git status --short`, `git branch --show-current`,
`git stash list`, `git log --oneline -1 --all` and `git diff` of the `shelf` repository.

## Scoring

Score each criterion 0, 1 or 2 and give one line of evidence (file and quote, or the command
and its output). Score what the outputs and repository states show. A criterion the output
never addresses scores 0 unless its row says otherwise.
