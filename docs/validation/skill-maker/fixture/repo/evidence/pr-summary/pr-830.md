## Summary

This PR addresses the rounding issue reported in the linked issue. To understand the problem I
first looked at how amounts flow from the API into the ledger. Amounts arrive as strings in the
request body, are parsed by the serializer, and are then converted to `Decimal` in
`ledger/money.py` before being posted.

While investigating I noticed that `to_minor_units` used `float` arithmetic in one branch. I
then traced the callers of `to_minor_units` and found three of them.

### Changes by file

- `ledger/money.py`: `to_minor_units` now uses `Decimal.quantize` with `ROUND_HALF_EVEN`
  instead of multiplying a float by 100 and calling `round`. I also renamed a local variable
  from `amt` to `amount` for readability.
- `ledger/posting.py`: updated the call to `to_minor_units` to pass the currency explicitly.
- `api/serializers/transfer.py`: updated the call to `to_minor_units` to pass the currency.
- `jobs/settlement.py`: updated the call to `to_minor_units` to pass the currency.
- `tests/test_money.py`: added six tests covering half-cent cases for IDR, USD and JPY.
- `tests/test_posting.py`: updated two fixtures for the new signature.

### Background

Floating point numbers cannot represent most decimal fractions exactly, which is why financial
code should use `Decimal`. Banker's rounding (`ROUND_HALF_EVEN`) is the convention our payment
provider uses, so this also brings us in line with their settlement files.

### Risk

Settlement totals for USD transfers that end in exactly half a cent will change by one cent
compared with before, because they now round to even. This affects the nightly settlement job.
