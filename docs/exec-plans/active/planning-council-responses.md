# Anonymous Council responses

Shared decision brief: planning-council-brief.md. Independent contexts, same model
family, five lenses in two waves due to the three-worker limit. Responses below
are concise faithful summaries; reviewer prompts do not disclose their authors.

## Response A

Improve task contract, template and execution preflight together without moving
the whole program into the plan. The present contract accepts "Change ... to
satisfy acceptance" and lifecycle template accepts "Concrete evidence-backed
step"; the supplied M2 combines foundation, Hero, About and quality gates.
Require verified starting state, file/symbol, add/replace/remove operation,
resulting behavior and snippets/replacement text where prose leaves a decision.
Discovery must write resolved contracts back before consumers start. Preflight
repairs ambiguous task detail from source within existing authority. Require
example reading and clarify that code snippets in plans are allowed. Cost is
writing/drift; use symbol anchors and focused checks. Test one end-to-end fixture
with a new executor and independent oracle, then verify installed native/nested bytes.

## Response B

The opportunity is a portable package of decisions. Existing exact paths,
interfaces and assertions are a strong base, but F3d's laptop size statement
still omits the formula, selector and values. Require per-task location, observed
starting state, selected operation, exact values and decisive change snippet.
Explicitly distinguish roadmap from executable tasks; align lifecycle template
and execution preflight. Make a short worked example mandatory and include exact
noncode replacement text. More detail costs tokens and can age; omit routine
bodies and pin source anchors. Compare old/new planners on identical fixtures,
execute from only their plans and verify setup resource identities.

## Response C

Strengthen readiness using existing contracts rather than copy every function.
Full code plans can be premature and consistently wrong. Current guide already
requires precision, while generic template and optional examples allow milestone
output. M2 is a roadmap, unlike the supplied enum insertion with exact values.
Require file/anchor, before-after or signature plus behavior, critical literals
and concrete checks. Snippets are needed when prose permits material divergence.
Change "planning writes ... not implementation code" to prohibit source edits
during planning, while allowing snippets in the plan. Execution must refine
ambiguous tasks without reopening locked decisions. Compare plans and blind
implementations on identical inputs with independent behavioral checks, measure
unresolved decisions/errors and verify installed bytes. Length is no quality proof.

## Response D

The goal is transferring decisions rather than expanding document length.
Current task template and generic lifecycle template still permit abstract
changes. Superpowers' enum insertion and replacement text carry actual decisions.
Require Change Specification: inspected initial state, symbol/location, operation
and final result, with snippets/text/pseudocode wherever prose leaves behavior
open. Separate work status from execution readiness. UNKNOWN interfaces can
remain in roadmap but discovery must resolve and populate consumer tasks first.
Use the same gate in execution. Snippets age; use symbol anchors and drift checks.
Test same-fixture old/new planning, fresh-context execution and an independent
oracle, counting material guesses and outcome variance; different user apps are
not causal evidence.

## Response E

A plan can look complete while implementation decisions remain missing. A new
executor needs "where do I change what into what?" Existing guidance has paths,
interfaces and assertions but M2 still leaves task design to the next model.
Require location, current condition, selected change and success observation;
use small diffs/snippets/exact text to prevent materially different outputs.
UNKNOWN gets bounded discovery, not an entirely abstract plan. Every task needs
reachable requirement context, producer interfaces, literals, command directory
and prerequisites. "Follow existing pattern" needs an actual file/symbol.
Tradeoff is length/drift; keep only decisions unavailable from surrounding code.
Compare identical fixtures in fresh planning/execution contexts, record guesses
and incorrect edits, and run an independent oracle. Heading count proves little.
