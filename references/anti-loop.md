# Progress and resource guards

These are behavioral guards unless the host exposes an enforceable control.
Andino coordinates their application; the selected skill owns the complete method
and required artifact. Bounded acquisition/transport must not erase decisions,
assertions, citations, required resources or acceptance evidence.

| Guard | Observable trigger and action | Exit / limit |
| --- | --- | --- |
| 1. Naive looping | Before an investigation/tool action identify the unresolved question and expected new signal. Same tool + materially same arguments + unchanged state: reuse the result. | Stop when the decision/acceptance is supported; if a second A -> B -> A -> B cycle adds no evidence, change hypothesis/approach or checkpoint the exact blocker. |
| 2. Context bloat | Search -> filter -> relevant range. Reuse stable rules, current guide activation and unchanged tool results; link durable artifacts rather than replaying chat/history/logs. | Refresh only after relevant drift or lost context. A selected skill's required resources still must be read; a bounded excerpt must not hide a material contradiction. |
| 3. MCP/tool bloat | Discover names/metadata first, then only the schemas and services needed for the current operation. Prefer a sufficient existing native/tool path. | Do not enable/connect every MCP, load all schemas, or install providers for routing completeness. Use lazy discovery/configuration only when actually supported and authorized; never claim already-injected definitions were unloaded. |
| 4. Excess reasoning | Match reasoning/model effort to uncertainty, consequence and coupling. Simple known work uses the least costly adequate supported setting; escalate for evidenced difficulty/risk. | Respect explicit user choices and real controls. No invented model selector, universal high effort, portable vendor-default claim or unmeasured savings claim. |
| 5. Tool ping-pong | Use one browser/diagnostic surface for the same question; another tool must resolve a distinct missing signal. | Playwright -> DevTools -> Playwright with unchanged state is not progress. Reuse evidence; return to the first tool only for changed state or a new discriminating check. |
| 6. Retry loops | Retry only transient failures, at most twice with backoff per unchanged operation, respecting a stricter host/service limit or retry instruction. | Do not retry schema, credentials, permission or daily-quota failures unchanged. Record the boundary and use an authorized sufficient alternative, never a denial bypass. |
| 7. Oversized tool output | Bound queries, row counts, ranges and supported output limits before calls. Read relevant log/DOM/SQL/source ranges instead of full dumps. | Retain complete material evidence in an authorized artifact when necessary; inspect focused sections. A truncated result is incomplete evidence, not a passed check. |
| 8. Unbounded AI output | Keep conversation updates concise; choose a deliberate artifact format/location for long deliverables. Use supported response/tool limits and any explicit user/host/task budget. | No invented universal word/token cap. Required code, specs and plans remain complete, using files or coherent chunks when transport requires them. Before a real limit, checkpoint unfinished work; never report it DONE. |
| 9. Overlapping skills | Select one method/provider per concern, plus distinct domain/research/verification support when actually needed. Load only current methods and their required resources. | Explicit choices and actual fit win; catalog presence is not activation. Stop duplicate methods, blanket bootstrap, memory/graph retrieval and skill chains by habit. |
| 10. Agent explosion | Default subagents zero. Delegate for required independence or materially useful bounded independent work under actual authorization. | At most three concurrently active direct workers, no nested spawning; serialize shared writes, verify results/integration. Schedule required participants in waves. No automatic planner -> agent -> reviewer -> verifier swarm for simple work. |

## Applying limits without weakening the work

Set a concrete exit condition for the current question/task, not a mandatory
numeric budget for every request. Use actual host output/model controls when
exposed; record real limits rather than pretending a skill can enforce runtime
token accounting, unload MCP schemas or change the model on every host.

Stop acquiring context when the next decision is sufficiently grounded, unless
acceptance, risk or contradictory evidence needs another check. Resume when new
evidence warrants it. A failed behavioral check calls for diagnosis, not repeated
unchanged verification. Rerun after relevant changes; stop when acceptance is
proven, an actual budget/stop condition is reached or a deterministic blocker
prevents progress. Checkpoint the gap and continue independent authorized work.

Concise checkpoints and responses point to full required artifacts. Compress
redundancy and completed history only when decisions/evidence remain recoverable.
Do not claim cache/token savings without measurements. Resource limits must not
turn incomplete work into a DONE claim.
