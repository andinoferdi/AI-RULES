# Consistency and revision propagation

Use for a contradiction, material revision or proposal/final consistency review. The [core matrix](../assets/research-core-templates.md) makes dependencies visible; filling its cells is not proof of consistency.

Check the chain: phenomenon/evidence → problem/gap → RQ → objective → theory/concepts → object/unit/scope → required data → design/collection/instrument → analysis → findings → discussion → conclusions/implications. Map each RQ to the evidence that can answer it and each claim back to a supported predecessor. Compare planned and actually executed methods explicitly.

Look for concrete broken links: title population differs from sampled population; experience question is answered only by regression; hypothesis uses a removed construct; analysis does not fit data; reported value has no output source; conclusion answers an unstudied question; causal language exceeds design; defense uses obsolete planned methods. Show the conflicting elements and provenance, practical impact, alternatives and decision needed. Do not silently choose a material research decision.

## Change impact

Capture exact supervisor/examiner feedback separately from interpretation. Record authority, date/artifact, requested change, confirmed decision and ambiguity. Preserve old approved decisions as history, not current truth after an authorized replacement.

| Change | Review affected dependencies |
| --- | --- |
| Title/focus | Problem, RQ, objectives, concepts/unit/context, design/data/analysis, outline. |
| RQ/objective | Evidence need, collection, analysis, title, relevant chapters and conclusion map. |
| Construct removed | Background, RQ, hypotheses, theory/framework, instrument, data dictionary, analysis and contribution. |
| Method | Sampling/participants, instrument, data, analysis, ethics/feasibility, BAB III, interpretation/causal wording and existing conclusions. |
| Finding/output | Registry, values/tables/figures/quotes, results, discussion, uncertainty, implications, conclusions and RQ map. |
| Conclusion | Finding support, RQ/objective coverage, scope and absence of new evidence. |
| Examiner revision | ResearchState, affected chapters, downstream dependencies, answer cards and final consistency. |

For each impacted artifact record current version, necessary change, owner/decision, evidence to recheck and disposition. Mark affected fields NEEDS_REVIEW; do not silently label them CONFIRMED. Preserve unaffected content. Resolve conflicting supervisor/examiner instructions with a focused clarification and continue unrelated edits.

Use checklist outcomes DONE, NEEDS_REVIEW, MISSING, BLOCKED, NOT_APPLICABLE, supported by evidence and a next useful action. They are checklist labels, not additional ResearchState field statuses. A section is not DONE just because text exists.

Final review compares title and BAB I–V, source/analysis locators, actual vs planned procedure, material null/contradictory findings, claim scope, conclusion support, guideline and unresolved revisions. Return the exact remaining inconsistency and affected claim; do not claim full thesis consistency from a single edited paragraph.
